# 올해검진 (checkup-window) — 올해 받을 수 있는 국가건강검진 확인하기

올해검진은 토스 앱(Apps-in-Toss)에서 동작하는 미니앱으로, 올해 받을 수 있는 국가건강검진 대상을 알려 줍니다. 본인과 가족 최대 9명의 이름, 출생연도, 성별, 건강보험 유형을 입력하면 올해 받아야 할 검진, 12월 31일까지 남은 일수, 앞으로 3년간 받게 될 검진을 보여 줍니다.

## 기능

- 🩺 **대상 확인:** 일반건강검진(보험 유형에 따라 주기가 다름)과 암검진(위암, 대장암, 유방암, 자궁경부암, 간암(조건부), 폐암(조건부, 54~74세))의 올해 대상을 계산합니다.
- 👨‍👩‍👧 **가족 프로필:** 본인 프로필 하나와 가족 프로필 최대 9개를 기기에 저장합니다.
- ✅ **수검 기록:** 검진마다 올해 받았는지 표시하면 결과 개수가 바로 바뀝니다.
- ⏰ **마감 배너:** 7월부터 12월까지 연말까지 남은 일수를 보여 주며, 30일 이내에는 강조 표시가 되고 이번 달에는 닫을 수 있습니다.
- 📅 **3년 계획:** 앞으로 3년 동안 연도별로 누가 어떤 검진을 받아야 하는지 보여 줍니다.
- 🎬 **리워드 광고 잠금:** 3년 계획과 가족 결과는 리워드 광고 뒤에 있습니다. 광고 슬롯이 설정되지 않았으면 광고 없이 바로 열립니다.
- 📢 **배너 광고 영역:** 광고 그룹 ID가 설정되어 있으면 배너 광고를 보여 줍니다.
- 📚 **기준과 출처:** 앱에 반영된 각 검진의 연령 범위, 주기, 법적 근거를 시트에서 확인할 수 있습니다.
- 🔗 **공유:** 홈 화면으로 바로 연결되는 토스 링크로 결과를 공유합니다.
- ⭐ **리뷰 요청:** 검진을 처음 받은 것으로 기록한 직후 한 번만 앱 리뷰를 요청합니다.
- 🗑️ **데이터 초기화:** 확인 후 모든 프로필, 기록, 배너 상태를 지웁니다.
- 🛡️ **손상된 데이터 복구:** 저장된 데이터가 검증에 실패하면 원본을 `.corrupt` 키에 보관하고 앱은 깨끗한 상태로 시작합니다.

## 기술 스택

- **프레임워크:** React 18 + TypeScript, Vite 6으로 빌드(클라이언트 사이드 렌더링만 사용하며, 번들은 토스 CDN에서 제공)
- **라우팅:** React Router 7 (`BrowserRouter`, `basename`은 `BASE_URL`에서 설정)
- **UI:** Toss Design System(`@toss/tds-mobile`, `@toss/tds-mobile-ait`)과 일반 CSS(`src/styles/`, `src/index.css`)
- **플랫폼 SDK:** 공유, 리뷰 요청, 햅틱, 분석, 광고에 `@apps-in-toss/web-framework` 사용
- **저장소:** 버전이 붙은 envelope(`{ version: 1, data }`)을 사용하는 브라우저 `localStorage`. 데이터베이스와 서버는 없습니다.
- **인증:** 없음. 사용자를 로그인시키지 않으며 어떤 API도 호출하지 않습니다.
- **테스트:** jsdom과 Testing Library를 쓰는 Vitest, 시각 스모크 테스트는 Playwright

## 시작하기

Node.js와 npm이 필요합니다(프로젝트는 `package-lock.json`을 사용합니다).

```bash
# 의존성 설치
npm install

# 타입 검사
npx tsc --noEmit

# 단위 테스트 실행
npx vitest run

# 프로덕션 번들 (결과물은 dist/)
npx vite build
```

토스 번들은 [배포](#배포) 절을 참고하세요.

## 환경 변수

`.env.example`을 `.env`로 복사한 뒤 값을 채웁니다. Vite는 빌드 시점에 이 값을 코드에 넣으므로, 값을 바꾼 뒤에는 다시 빌드해야 합니다. 값이 비어 있으면 해당 기능이 조용히 빠집니다.

| 변수 | 설명 | 필수 여부 |
|---|---|---|
| `VITE_TOSS_AD_GROUP_ID` | 앱인토스 콘솔에서 발급받은 배너 광고 그룹 ID. 비어 있으면 배너를 그리지 않습니다. | `npm run build:release`에서 필수 |
| `VITE_TOSS_AD_SLOT_ID` | 콘솔에서 발급받은 리워드 광고 슬롯 ID. 비어 있으면 잠긴 영역이 광고 없이 열립니다. | `npm run build:release`에서 필수 |
| `VITE_SHARE_OG_URL` | 공유 링크에 붙는 미리보기 이미지 URL. 비어 있으면 미리보기 이미지 없이 링크만 공유됩니다. | 아니오 |

`.env.example`에는 `VITE_TOSS_IAP_SKU`와 `VITE_TOSS_PROMOTION_CODE`도 있지만, 현재 소스는 이 두 값을 읽지 않으므로 효과가 없습니다.

콘솔에서 발급된 ID는 소스 코드에 직접 적지 마세요. 광고 변수 두 개 중 하나라도 없으면 릴리스 빌드가 실패합니다(`scripts/check-release-env.mjs`).

## 프로젝트 구조

```
src/
├── pages/          # Home(결과)과 ProfileForm(프로필 생성/수정)
├── components/     # TDS를 감싼 공용 UI 래퍼. home/에는 홈 화면 섹션이 있음
├── domain/         # 순수 대상 판정 규칙, 계획, 배너 로직, 포맷팅
├── data/           # localStorage 저장소와 검진 스토어 provider
├── lib/            # 분석, 리뷰, 공유 래퍼, 공용 타입, 저장소 헬퍼
├── styles/         # 전역 CSS와 리워드 광고 CSS
├── __tests__/      # Vitest 테스트 모음
└── test/           # 테스트 공용 렌더 헬퍼
e2e/                # Playwright 시각 스모크 테스트
scripts/            # 릴리스 환경 변수 및 출시 전 점검 스크립트
```

## 배포

1. `.env`에 콘솔에서 발급받은 광고 ID를 채웁니다.
2. `npx ait build`로 앱인토스 번들을 빌드합니다. `apps-in-toss.config.ts`의 `appName`은 앱인토스 개발자 콘솔에 등록된 앱 이름과 완전히 같아야 하며, 다르면 4031 오류로 배포가 실패합니다.
3. 생성된 `.ait` 번들을 앱인토스 개발자 콘솔에 업로드하고 심사를 요청합니다.
4. 제출 전에 빌드에 테스트 광고 ID나 자리표시자 값이 없는지, 그리고 심사 체크리스트(외부 링크, 콘솔 오류, 공유와 리뷰 진입점)를 통과하는지 확인합니다.

이 앱은 정적 번들입니다. 서버 사이드 렌더링이나 API 라우트는 사용할 수 없습니다.
