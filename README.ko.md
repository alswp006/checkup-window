# Checkup Window (올해검진) — 올해 받을 수 있는 국가건강검진을 한눈에

Checkup Window(올해검진)는 출생연도, 성별, 보험 유형에 국가건강검진 기준을 적용해 주는 App-in-Toss 미니앱입니다. 올해 대상 검진 항목 체크리스트, 12월 31일까지 남은 일수, 대상이 아닌 항목이 다시 대상이 되는 연도를 보여 줍니다. 건강보험공단 앱이나 기준표를 뒤지지 않고도 연말 전에 검진을 예약하려는 국내 성인을 위해 만들었으며, 모든 프로필과 검진 기록은 기기 안에만 저장됩니다.

## 주요 기능

- 🧾 **프로필 등록:** 이름, 출생연도, 성별, 보험 유형(직장가입자, 지역가입자, 직장가입자의 피부양자, 의료급여 수급자 등)을 입력해 나를 추가합니다.
- 👨‍👩‍👧 **가족 프로필:** 가족 최대 9명을 추가할 수 있으며(총 10개 프로필), 프로필마다 체크리스트가 따로 있습니다.
- ✅ **7개 검진 항목의 대상 여부:** 일반건강검진, 위암·대장암·유방암·자궁경부암·간암·폐암 검진을 주기(매년 또는 2년마다)와 연령·성별 규칙에 따라 판정합니다.
- 🩺 **조건부 항목:** 간암과 폐암 검진은 조건부 항목으로 표시되며, 바텀시트에서 확인한 뒤에 대상으로 표시됩니다.
- 🔄 **받음 표시:** 항목마다 올해 받았는지 표시할 수 있고, 요약과 진행률 바가 바로 바뀝니다.
- ⏳ **연말 카운트다운:** 12월 31일까지 남은 일수와, 올해 대상이 아닌 항목의 다음 대상 연도를 보여 줍니다.
- 🔔 **마감 배너:** 7월부터 미확인 항목을 알리는 배너가 뜨며, 연말 30일 전부터는 긴급 상태로 바뀝니다. 이번 달에는 닫을 수 있습니다.
- 📅 **3년 계획:** 프로필마다 3년치 검진 일정을 보여 주며, 리워드 광고를 본 뒤에 열립니다. 광고를 띄울 수 없으면 자동으로 열립니다.
- 📤 **공유:** 결과를 공유하면 받는 사람이 홈 화면으로 바로 들어옵니다.
- ⭐ **리뷰 요청:** 항목을 처음 받음으로 표시한 직후 한 번만 앱 리뷰를 요청합니다.
- 📚 **기준과 근거:** 검진 항목마다 적용 기준과 법적 근거를 시트에서 확인할 수 있습니다.
- 🗑️ **초기화:** 확인 후 모든 프로필, 기록, 배너 상태를 지웁니다.

## 기술 스택

- **프레임워크:** React 18, TypeScript, Vite 6 (정적 클라이언트 사이드 빌드, SSR 없음)
- **라우팅:** React Router 7 (`BrowserRouter`)
- **UI:** `@toss/tds-mobile`(Toss Design System) 컴포넌트. `@emotion/react`와 `@emotion/styled`는 peer dependency로 함께 씁니다. 레이아웃은 flex/grid용 가벼운 CSS만 쓰고, 다크 모드는 `var(--adaptive*)` CSS 변수로 처리합니다.
- **App-in-Toss SDK:** `@apps-in-toss/web-framework` (공유, 햅틱, 광고, 분석, 리뷰를 위한 imperative API)
- **저장소:** 버전이 붙은 키(`checkupWindow.*.v1`)를 쓰는 브라우저 `localStorage`. 서버와 데이터베이스는 없습니다.
- **인증:** 없음. 토스 로그인을 쓰지 않으며 계정 없이 동작합니다.
- **테스트:** Vitest, Testing Library, jsdom, 비주얼 스모크 테스트용 Playwright

## 시작하기

```bash
# 의존성 설치 (pnpm이 아니라 npm 사용)
npm install

# 타입 검사
npm run typecheck

# 단위 테스트
npm run test

# 프로덕션 번들 (dist/에 생성)
npx vite build

# 비주얼 스모크 테스트 (처음이라면: npx playwright install chromium)
npm run test:visual
```

## 환경 변수

`.env.example`을 `.env`로 복사한 뒤 앱인토스 콘솔에서 발급받은 값을 채웁니다. Vite는 빌드 시점에 이 값을 치환하므로, 값을 바꾼 뒤에는 다시 빌드해야 합니다. 값이 비어 있으면 해당 기능은 조용히 빠집니다.

| 변수 | 설명 | 필수 여부 |
|----------|-------------|----------|
| `VITE_SHARE_OG_URL` | 공유 링크에 붙는 미리보기 이미지 URL. 비어 있으면 미리보기 이미지 없이 링크만 공유됩니다. | 아니오 |
| `VITE_TOSS_AD_GROUP_ID` | 콘솔에서 발급받은 배너 광고 그룹 ID. 비어 있으면 배너 광고를 렌더링하지 않습니다. | 아니오 |
| `VITE_TOSS_AD_SLOT_ID` | 콘솔에서 발급받은 리워드 광고 슬롯 ID. 비어 있으면 리워드 게이트가 자동으로 열립니다. | 아니오 |

`.env.example`에는 `VITE_TOSS_IAP_SKU`와 `VITE_TOSS_PROMOTION_CODE`도 적혀 있지만, 현재 어떤 화면도 이 값을 읽지 않습니다.

## 프로젝트 구조

```
src/
├── App.tsx          # 라우트 (/, /profile/new, /profile/:profileId/edit)
├── main.tsx         # 진입점 (TDS provider와 router)
├── pages/           # Home(결과), ProfileForm(입력과 수정)
├── components/      # 공용 UI (Card, SummaryHero, SubmitFooter, StateView 등)

├── domain/          # 순수 판정 규칙과 계산 (UI와 저장소에 의존하지 않음)
├── data/            # localStorage 저장소와 checkup store provider
├── lib/             # 타입, 분석, 공유, 리뷰, 저장 헬퍼
└── __tests__/       # 공용 테스트 헬퍼와 테스트
e2e/                 # Playwright 비주얼 스모크 테스트
```

## 배포

Checkup Window는 정적 번들로 토스 CDN에 배포합니다.

1. `apps-in-toss.config.ts`의 `appName`이 앱인토스 개발자 콘솔에 등록된 앱 이름과 대소문자까지 정확히 일치하는지 확인합니다. 일치하지 않으면 4031 배포 에러가 납니다.
2. 콘솔에서 발급받은 값을 `.env`에 채웁니다(환경 변수 절 참고). `.env`는 커밋하지 마세요.
3. `npx ait build`로 토스용 번들을 빌드합니다. `.ait` 파일이 생성됩니다.
4. 앱인토스 개발자 콘솔에 빌드를 업로드하고 심사를 요청합니다.
5. 제출 전에 심사 기준을 확인합니다. 미성년자 대상 콘텐츠가 없어야 하고, 외부 이동이 없어야 하며, 프로덕션에 `console.error`가 없어야 하고, 외부 요청은 CORS에 안전해야 합니다(현재 외부 요청은 없습니다).
